## 3. クロップの方法

端末の生キャプチャは **720×1520 = 比 2.111**。Play は
**「最大辺は最小辺の 2 倍を超えてはならない」**と定めているので、**生のままでは要件違反**。
9:16（720×1280 = 比 1.778）に落とす必要がある。

- `01` `02` `03` `05` `06` … **上端から** 720×1280（ステータスバーを残し、ナビゲーションバーを落とす）
- `04` … **下端から** 720×1280（`y=240..1520`）

> **04 だけ下端基準にしている理由:** 「このアプリについて」はスクロールの最後尾にあり、
> 「ソースコード」の URL が y=1288 に来る。上端基準で 1280 に切ると**この URL だけが欠ける**。
> 画面の目的（アプリ内にプライバシーポリシーとソースコードへの導線があること）が
> 伝わらなくなるので、ここだけ揃えるより欠けないほうを取った。
> 代償はステータスバーが写らないことだが、ストア画像としてはむしろ無害。

再現コマンド（リポジトリのルートで。Pillow 12.3.0 で確認）:

```bash
python3 - <<'PY'
from PIL import Image
PLAN = {'01-home':0, '02-rules':0, '03-advanced-top':0,
        '04-advanced-about':240, '05-records':0, '06-exclusions':0}
for name, top in PLAN.items():
    src = Image.open(f'store/screenshots/raw/{name}.png')
    assert src.size == (720, 1520)
    src.crop((0, top, 720, top + 1280)).convert('RGB').save(
        f'store/screenshots/{name}.png', 'PNG', optimize=True)
PY
```

`.convert('RGB')` が必須。`screencap -p` の出力は **RGBA（PNG color type 6）** で、
Play は 24bit PNG（アルファなし）を要求する。

## 4. Play の仕様との照合

出典: https://support.google.com/googleplay/android-developer/answer/9866151
（2026-09-18 に再確認。`PLAY-RELEASE.md` §6 の表と同じページ）

| 要件 | 実測 | 判定 |
|---|---|---|
| スマートフォン 最低 2 枚 / 最大 8 枚 | 6 枚 | ✅ |
| JPEG または **24 ビット PNG（アルファなし）** | 全 6 枚 `RGB` / bitdepth 8（PNG color type 2） | ✅ |
| **最小辺 320 px 以上** | 720 px | ✅ |
| **最大辺 3840 px 以下** | 1280 px | ✅ |
| **最大辺 ≤ 最小辺 × 2** | 1280 / 720 = **1.778** | ✅ |
| 縦 9:16 | 720×1280 = 9:16 ちょうど | ✅ |

ファイルサイズは 64〜168 KB（スクリーンショットに上限の記載は無い）。

### ⚠️「最小 1080×1920」は必須要件ではない

`PLAY-RELEASE.md` §6 の表は「縦 **9:16**（最小 1080×1920）」と書いているが、
これは**必須要件と推奨枠を 1 行に潰してしまっている。** 原文を読み直した結果:

- **必須**は「最小辺 320 px / 最大辺 3840 px / 最大辺は最小辺の 2 倍以内」だけ。
  720×1280 は**この必須要件を満たす。提出はできる。**
- **1080 px は別の条件。** 「スクリーンショットを使う形式でのレコメンド対象になるには、
  **1080 px 以上のスクリーンショットを 4 枚以上**（横 16:9 = 最小 1920×1080 /
  縦 9:16 = 最小 1080×1920）」という**露出のための要件**。

> To be eligible for recommendations in formats that use screenshots, for apps you must provide
> at least four screenshots with minimum 1080px resolution.

→ **この 6 枚で提出は通るが、1080 px 未満なのでレコメンド枠には載らない。**
S25（1080×2340）で撮り直せば 1080×1920 にクロップでき、その枠に入れる。§5 参照。

## 6. 目視確認の結果（2026-09-18）

6 枚すべてを画像として開いて確認した。**数値チェックだけでは足りない**（文字化けしても寸法は正しいため）。

- 文字化け（豆腐）**なし**。日本語がすべて正しく描画されている
- レイアウト崩れ**なし**。テキストの見切れ、カードの重なりは無い
- ステータスバーへの潜り込み**なし**（Android 11 なので edge-to-edge は強制されない）
- **個人情報の写り込みなし** — 通知アイコンはデモモードで非表示、発信記録と除外リストは空、
  表示されている番号は `09012345678` / `0312345678` / `05012345678` の**サンプル値のみ**

### 撮影中に確認できたこと（スクリーンショット以外）

- インストール: `adb install -r` が `Success`。play 版なので通話履歴の権限は要求されない
  （`dumpsys package` の requested permissions は `READ_PHONE_STATE` と内部権限の 2 つだけ）
- 起動からの一連の操作で **`AndroidRuntime:E` のクラッシュはゼロ**
- 通話リダイレクトのロール付与ダイアログが出て、許可すると 01 の警告カードが消えることを確認
- 「このアプリについて」→「プライバシーポリシー」のタップで **Chrome が起動する**ことを確認
  （`ACTION_VIEW` の導線が実際に動く。Play の必須要件の実地確認）

> ⚠️ **ただし開いた先は GitHub Pages の 404 だった。**
> `https://tmlksu.github.io/prefix-dialer/privacy.html` はホストからの `curl` でも **404**。
> 原因は「Pages が未有効」ではなく、そもそも **`docs/` を含むコミットが push されていない**こと
> （`origin/main` は `6873bab` 止まり）。**push と Settings → Pages の有効化は作者の作業。**
> これが済むまで、アプリ内のリンクも Play Console に登録する URL も 404 のままになる。
